# Accounts, sign-in and sessions

Part of the decisions in `docs/DESIGN.md` section 7. Rules: Sign-in codes, session length, open account questions.

- Session length (decided and built 2026-11-09, owner's request, for security: someone who gets hold of a person's computer must not be able to bid): a signed-in browser is signed out after **2 hours without being used** on the storefront and **1 day** in the admin app, instead of 30 days. It is an idle timeout, not a time since sign-in: `proxy.ts` in each app runs Auth.js on every page request, which re-signs the session JWT and pushes its expiry (and the cookie's) forward, so a browser in use stays signed in. The lengths are `SESSION_MAX_AGE_SECONDS` in each app's `lib/session-lifetime.ts`. An older 30-day cookie is replaced by a 2-hour or 1-day one on its next request.
- An emailed 6-digit code on every sign-in (2026-10-30). Sign-up sends a code and goes to the code page. Later sign-ins: password, then code. A correct code verifies the email. Codes last 10 minutes, are single-use, lock after 5 wrong tries, and a new code voids the old. Signing up again with an unverified email replaces that account's name and password, so nobody can block an address they don't own; a verified email gives 409. After a code is sent, another for the same account answers 429 `CODE_COOLDOWN` for 30 seconds, checked only after the password is right so it reveals nothing. **Send a new code** (2026-11-06): the code page of the storefront and the admin app has a button, disabled for 30 seconds like the server's cooldown. `POST /auth/login/resend` takes only the email and always answers 204, whether or not it sent anything, so it reveals nothing about accounts. It sends only if the account's password step passed in the last 30 minutes (`LoginCode` still exists, even expired), the cooldown has passed, and fewer than 5 new codes were sent in this sign-in (`LoginCode.resends`, reset by the next password step); it never sends to a banned account. The new code replaces the old.
- Username squatting: an unverified sign-up holds its username. Decide a cleanup rule for stale unverified accounts before launch.
- Account deletion must refuse or anonymise accounts with bids.
