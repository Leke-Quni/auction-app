# Tooling and hosting

Part of the decisions in `docs/DESIGN.md` section 7. Rules: Test runner, Fly, speed, DB pool, email, images, search host and sync.

- Query library for server data: React Query or SWR.
- Test runner Vitest; package manager Yarn 4 with the `node-modules` linker; Docker Desktop for local Postgres and Redis (2026-10-30).
- API host: Fly.io free trial, no card (owner won't add one). App `auction-api-leke`, region `fra`, `fly deploy -c apps/api/fly.toml --ha=false`. The trial stops the machine 5 minutes after each start and restarts it on the next request (+3-4 s). Consequence: the API can vanish mid-request, so bids use idempotency keys, state is re-checked after failures, the live feed reconnects and resyncs, and nothing lives only in API memory. Web on Vercel, database on Neon (Frankfurt), email on Resend.
- Speed (measured 2026-11-05): the app felt slow for three reasons. (1) The Vercel apps ran in Washington D.C. (the default, `iad1`) while the API and database are in Frankfurt, so every API call from a page crossed the Atlantic; `apps/web/vercel.json` and `apps/admin/vercel.json` now set `"regions": ["fra1"]` (the Vercel project's Function Region setting must agree). (2) Pages asked for their data one request after another: the listing page made 4 in sequence and the home page 2 waves; they now ask for everything at once (the listing page makes its order request second, only for an ended sale), with 100 ms added to every API call a load went from 236 to 121 ms (home) and from about 340 to 118 ms (listing), and `/categories` (an hour) and the top price (a minute) are kept by Next instead of being asked for on every view (`rarelyChanging`); the admin check `/admin/me` is shared by the layout and the page of a request. (3) The Fly trial stops the machine 5 minutes after each start, whatever `fly.toml` says (confirmed from Fly's own event log: started 15:18:15, stopped by Fly at 15:23:15), and the next request pays a boot of about 5 seconds; sockets drop and the background sweeps pause in between. It cannot be configured away without a card. To shrink the stopped time, ping `https://auction-api-leke.fly.dev/health` every minute from a free external scheduler (for example cron-job.org); with pings, the API is stopped for at most about a minute of each cycle instead of until the next visitor. Not done: moving the API somewhere that does not stop (the owner won't add a card), and a "waking up" message in the web app.
- Database pool (2026-11-06): `packages/db` sets the pool explicitly: `DB_POOL_MAX` (default 10) connections per process and `DB_CONNECT_TIMEOUT_MS` (default 10,000) to get one, after which the request fails rather than hanging (a bid answers 503 `BUSY`; the pg pool's timeout is a plain error with no Prisma code, so `bidFailure` matches its message; other routes would answer 500) behind bids queued on a hot auction's row lock.
- Email: the API sends through Resend directly (`RESEND_API_KEY`, `MAIL_FROM`); production refuses to start without a key; a failed send is 503. Without a verified domain, Resend's sandbox delivers only to the account owner's address.
- Images: a public Vercel Blob store with OIDC and presigned uploads (no long-lived token). The browser uploads via a short-lived URL from `apps/web/app/api/uploads` (own folder, JPG/PNG/WebP, 5 MB). The API accepts only Blob URLs in the seller's own folder and reports removed photos; the web app deletes them, because OIDC works only on Vercel.
- Search host: self-hosted Typesense in Docker Compose, not Cloud (2026-11-02). Cloud's free allowance is one-time and may need a card; the Fly trial machine cannot host it. The code uses a `SearchIndex` interface, so Cloud can be swapped in. Without `TYPESENSE_URL`/`TYPESENSE_API_KEY` the API falls back to `PostgresSearchIndex`, built to match Typesense (whole words plus prefix on the last word, typo tolerance via `fuzzystrmatch`, synonyms, repeated letters cut to two, most-words fallback). `apps/api/test/search-parity.e2e.test.ts` requires equal results from both. Known difference: a swapped letter pair is two typos in Postgres, one in Typesense.
- Search sync is direct from the API, not through an outbox (2026-11-02): listing saves update Typesense; a sweep (start-up and every 5 minutes) and `reindex` repair gaps; searches also filter ended auctions by end time. `BidPlaced` partially updates price, bid count, final-chance and end time, throttled to once per auction per 5 seconds, but extensions go at once.
