# Listings, Q&A and notifications

Part of the decisions in `docs/DESIGN.md` section 7. Rules: Listing lifecycle, public Q&A, reports on posts, in-app notifications.

- Lifecycle: a seller saves a draft, adds photos, then publishes now or at a start time up to 30 days ahead; the end is fixed at publish. Drafts are private and fully editable. After publishing only description and photos change (one photo minimum), and only until the first bid: from then on they are fixed too (decided 2026-11-11, from the audit: bidders bid on what they saw, and a seller could swap the photos and text after people had bid). Both writes check `bidCount = 0` in the same statement or transaction that changes them, so a simultaneous bid wins or the edit is refused with 409. With bids, the edit page shows a note and only the pickup address editor, and the listing page's link reads "Edit pickup address". Once an auction has ended (end time passed or closed) the seller can neither edit nor remove it, with or without bids (decided 2026-11-09, owner's request: the system handles ended auctions); the seller's only options are "list it again" for an unsold one and the pickup address correction for a sold one. The Edit links are hidden and the edit page redirects to the listing. A draft can be deleted, and a published listing can be removed until it has a bid (checked and deleted in one statement). Editing a just-published draft answers 409. Publishing reads the listing again under its row lock and writes in the same transaction (2026-11-11, from the audit), and a photo change on a draft touches the same row, so simultaneous publishes publish once (the rest answer 409) and schedule one close, and a listing cannot be published with its last photo being removed.
- Public Q&A only. Any signed-in user except the seller may ask on a published, unended auction (up to 1,000 chars); the seller answers once (up to 2,000). Writers can edit or delete their own post until the auction ends (a seller can still post a first answer after); a seller cannot delete a buyer's question but can take back their own answer. Edits show "(edited)" and send no notification. A warning above the box says to keep conversations on the site. If a user is later deleted, their question shows "<deleted user>" and the stored text must be blanked by delete-account.
- A new question notifies the seller and an answer the asker: live toast, bell entry, and email, all best-effort.
- Each question and answer has like/dislike votes; the asker can't vote on their own question, the seller can't vote.
- Limits: 10 questions and 10 reports a minute per person. Reports (reason: spam, abusive, contact details, other) are saved with the words as written, one per person and post, with no foreign keys so they outlive the post until the admin app handles them (handled ones go after 30 days). A post that seems to contain an email or phone number is published but also saved as a reporter-less `CONTACT_DETAILS` report (`containsContactDetails`).
- Every post, edit and deletion is written to `QuestionLog` (no foreign keys, for the admin app) in the same transaction. Log entries and deleted questions are removed 30 days after the auction ends (`QUESTION_LOG_RETENTION_DAYS`).
- In-app notification list: notifications live 14 days; a bell shows the unread count and the latest 20; clicking one marks it read and opens its listing. A newer notice with the same key replaces the older and marks it unread. Expired rows are hidden at once and deleted hourly.
- Photo checks (2026-11-11, from the audit): `POST /listing-images/unused` looks only at photo addresses in the asker's own folder on our store (`isOwnImageUrl`) and leaves every other address out of the answer, whether or not a listing uses it, so it cannot be used to find out what someone else uploaded. Saving photos on a listing now also requires an image extension (jpg, jpeg, png or webp, what the upload route issues tokens for) and, when `BLOB_PUBLIC_HOST` is set, exactly that host; without it any Vercel Blob public store is accepted, which lets a seller use a store of their own and skip the size and type limits. **To do before launch: set `BLOB_PUBLIC_HOST` on the API (Fly secret) to the host of an uploaded photo's address, like `abc123.public.blob.vercel-storage.com`. Docs say the store id is the subdomain but not in which form, so copy it from a real photo address.**
